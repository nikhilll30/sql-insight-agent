-- 02 · self-correction

The interesting part is when the SQL is wrong.

Ask for “total revenue by country” and there is a trap: Invoice has no Revenue column. A text-to-SQL script would return a stack trace. The agent treats the database error as just another observation — and fixes itself. This exchange is from a real run:

attempt 1 · fails
SELECT BillingCountry,
       SUM(Revenue) AS TotalRevenue
FROM Invoice
GROUP BY BillingCountry
ORDER BY TotalRevenue DESC;
← OperationalError: no such column: Revenue
attempt 2 · after re-reading the schema
SELECT BillingCountry,
       SUM(Total) AS TotalRevenue
FROM Invoice
GROUP BY BillingCountry
ORDER BY TotalRevenue DESC;
← 24 rows · USA $523.06, Canada $303.96, France $195.10 …

Two things make this work. handle_parsing_errors=True keeps the loop alive instead of raising, so the SQLite error is fed back to Claude as an observation. And the toolkit includes sql_db_schema, so the agent's natural next move — go look at the actual columns — is a tool call away. The correction isn't a hard-coded retry; it's the same reasoning loop, one turn later. Run python error_recovery.py in the repo to watch it live, including the question about customer ratings that the agent correctly refuses to invent an answer for.

-- 05 · design decisions

Choices a code reviewer would ask about.

The small calls that separate a demo from something you can leave running.

a.Build the agent once, at import time

Constructing the LangChain agent means loading the schema and wiring the toolkit. Doing it per-request would add seconds to every query; doing it at startup means the first user pays nothing extra.

# main.py — module scope, not inside the route
db    = SQLDatabase.from_uri(f"sqlite:///{DATABASE_PATH}")
agent = create_sql_agent(llm=llm, db=db,
                         verbose=True,
                         handle_parsing_errors=True)

b.Temperature 0, model pinned by env

SQL generation wants determinism, not creativity. The model id lives in ANTHROPIC_MODEL so a model upgrade is a config change and a redeploy — no source edit, no rebuild of trust in the diff.

llm = ChatAnthropic(
    model=os.getenv("ANTHROPIC_MODEL", "claude-sonnet-4-6"),
    temperature=0,
)

c.Errors are observations, not exceptions

handle_parsing_errors=True routes malformed SQL and database errors back into the loop as feedback. That single flag is what turns “text-to-SQL script” into “agent” — see the self-correction section above for it working.

agent = create_sql_agent(
    llm=llm, db=db,
    handle_parsing_errors=True,  # errors → observations
    verbose=True,                 # full trace in logs
)

d.Design for the free tier's worst moment

Render's free tier sleeps after inactivity, so the UI's first job is honesty: probe /health, tell the user the server is waking, and poll up to a minute before sending their question anywhere.

# app.py — wake_up_backend_if_needed()
for attempt in range(1, max_retries + 1):
    if check_backend_status():
        return True
    time.sleep(retry_delay)
